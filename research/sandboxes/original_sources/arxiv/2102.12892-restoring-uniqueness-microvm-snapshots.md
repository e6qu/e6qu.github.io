## Summary
From the AWS Lambda/Firecracker team. Snapshotting an initialised microVM and cloning it fixes cold starts, but creates two security problems: snapshots contain high-value memory such as secrets, and every clone starts with identical state (RNG seeds, UUIDs, nonces). The paper surveys solutions and proposes two kernel interfaces, MADV_WIPEONSUSPEND and SysGenId.

## Key points
- Code initialisation tends to dominate serverless cold start; post-init snapshots address it.
- Cloning breaks uniqueness: UUIDs, secrets, nonces may repeat across clones.
- Proposed interfaces: MADV_WIPEONSUSPEND (wipe memory on suspend) and SysGenId (generation ID to notify guests of a restore).

## Excerpts
> "Cloning introduces the challenge of restoring the uniqueness of the VMs, to allow them to do unique things like generate UUIDs, secrets, and nonces." (Abstract)

## Relevance to the talk
A subtle hazard of "fork a warm sandbox per agent": identical clones share randomness and any secrets in the snapshot. Good footnote for agent-sandbox pools built on snapshot/clone.
