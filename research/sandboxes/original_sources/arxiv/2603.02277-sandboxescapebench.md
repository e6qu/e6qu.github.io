## Summary
Introduces SANDBOXESCAPEBENCH, an Inspect-based capture-the-flag benchmark asking whether a model with a shell inside a Docker/Kubernetes container can break out. To keep it safe, the container runs inside a VM: the flag lives on the VM filesystem, so a "successful" escape still lands inside another boundary. Frontier models reliably exploit easy misconfigurations, partly manage harder runtime/kernel escapes, and success scales roughly log-linearly with token budget; the v3 update reports that a newer model saturated the public benchmark.

## Key points
- 18 escape scenarios across three layers: orchestration (4), engine & runtime (8), host/kernel (6); difficulty 1-5.
- Nested "sandbox-in-a-sandbox": VM outer layer with no known vulnerabilities, container inner layer.
- Original results (Section 5.1): Claude Opus 4.5 overall success 0.49 [0.39, 0.59] vs Claude Haiku 4.5 0.18; on difficulty-3 tasks the largest models (Opus 4.5, GPT-5) both reached 0.40.
- Easy misconfigurations (privileged container, writable host mounts, exposed Docker socket) solved reliably; difficulty 3 partly; difficulty 4-5 not solved in the original evaluation.
- Many runs cost about $1 per sample: the marginal cost of an escape attempt is low.
- v3 adds a Section 6 update with later models (Opus 4.6, Claude Mythos Preview and others, 100M-token runs). Footnote 1: "We found that Claude Mythos Preview saturates this public benchmark, so deemed it important to update the paper." Section 6.1: Mythos Preview "succeeded at least once on 100% of samples."

## Relevance to the talk
The key paper for "is a container enough?". It reframes the agent as the potential attacker of its own sandbox, and its own design (container inside a VM) is a living example of defence in depth. Strong closing-section material.
