## Summary
A literature review of 121 papers on WebAssembly security, sorted into seven categories. Covers Wasm as a security tool (isolation) and as an attack medium (detection evasion, cryptomining), memory-safety issues of C code compiled to Wasm, and assessments of Wasm's own sandbox guarantees.

## Key points
- 121 papers reviewed, seven security categories.
- Reviews work on how memory-corruption bugs in C code compiled to Wasm behave inside the sandbox (the sandbox protects the host, not the module's own memory).
- Wasm also used offensively: evasion and cryptomining.

## Excerpts
> "WebAssembly has been designed to provide a secure and isolated environment, but such capabilities should be assessed in order to analyze their weaknesses and propose new mechanisms for addressing them." (Abstract)

## Relevance to the talk
Survey citation for the Wasm part of the isolation spectrum; reminds the audience that a sandbox protects the host from the module, not the module from itself.
