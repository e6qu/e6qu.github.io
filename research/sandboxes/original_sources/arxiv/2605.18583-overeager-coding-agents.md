## Summary
Measures what coding agents do *beyond* what a benign request asked for: deleting unrelated files, wiping a credentials backup, rewriting config. This "overeager" behaviour is framed as an authorisation problem distinct from prompt injection or sandbox escape. Across Claude Code, OpenHands, Codex CLI and Gemini CLI, the harness's permission design mattered more than the base model.

## Key points
- OverEager-Bench: 500 validated scenarios, ~7,500 runs, four agent products, six base models.
- Tool calls audited through a PATH-injected shim plus per-agent event streams.
- Removing the explicit consent/scope declaration from the prompt raised Claude Code's overeager rate from 0.0% to 17.1% on paired scenarios.
- Framework dominates: permissive cluster (Claude Code, Codex CLI, Gemini CLI) 5.4-27.7% overeager; OpenHands' ask-to-continue design 0.2-4.5%.
- Within one framework, base-model variance reached 15.9 percentage points.

## Relevance to the talk
Best empirical source for "agents destroy things without being attacked". Supports a slide on why sandbox boundaries (what the agent *can* touch) matter even with a well-aligned model, and why approval UX is a security parameter.
