## Summary
Coding-agent harnesses intercept out-of-sandbox actions and ask the user, and to reduce approval fatigue they let users save "allow-rules" the agent proposes. This paper shows untrusted repository content can steer the agent into proposing a plausible but very broad allow-rule; once approved, the rule silently blinds the harness for future malicious actions. Demonstrated on Claude Code and Codex CLI.

## Key points
- Attack target: the permission-update process, not the sandbox itself.
- Agents elicited the attacker's target allow-rule in 58% of experimental instances.
- Acquired rules covered 56.9% of category-specific capability test cases ("semantic blast radius").
- Conditional on approval, verified silent goal completion in 47 of 58 eligible instances (81.0%).

## Excerpts
> "untrusted context can influence the permissions presented for approval, with consequences extending beyond the immediate task." (Abstract)

## Relevance to the talk
Human-in-the-loop is part of the sandbox's TCB, and it can be socially engineered by the very agent it supervises. Strong slide for "approval prompts are not a boundary"; echoes classic UAC/permission-fatigue lessons.
