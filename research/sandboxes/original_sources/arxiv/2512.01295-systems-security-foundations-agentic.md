## Summary
A research agenda that reads agent security through classic systems-security principles (TCB, reference monitor, complete mediation, least privilege, information flow), with 11 case studies of real attacks on agentic systems. Its central point: the LLM is now inside the trusted computing base but behaves probabilistically, so classic guarantees become statistical at best, and the right layer for mediation is unclear.

## Key points
- Open problems (Section 5): instruction/data separation (a W^X analogue), least-privilege access control (writing the policy is itself unsolved), information-flow control through LLMs ("label explosion"), guarantees from probabilistic TCBs, security-aware model architectures, and when to treat an LLM as program vs fallible human.
- Prompt injection compared to dynamic code loading.
- Tool-call-only enforcement leaves gaps in complete mediation.
- Agents modifying their own security configuration treated as a tamper-resistance violation.
- Notes that in-context sandboxing is "unavailable or probabilistic at best"; cites IsolateGPT and ceLLMate as isolation examples.

## Excerpts
> "an agent typically has uniform access to all tool calls, whether necessary for the current task or not." (Section 5.2)

> "Without precise security assumptions, it is very challenging to build provable defenses." (Section 6)

## Relevance to the talk
The best single source for the "open problems" slide, written by systems-security people and explicitly connecting agent sandboxing to decades of OS-security doctrine.
