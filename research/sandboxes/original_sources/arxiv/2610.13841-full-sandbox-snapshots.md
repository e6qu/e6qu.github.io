## Summary
Instead of retrying a failed coding-agent run from scratch, restore and branch from intermediate full-machine snapshots (Go-Explore-style search over Daytona snapshots). Gains come mostly from state *outside* the repository: databases, running services, other runtime state that a git diff cannot reconstruct.

## Key points
- Go-Explore-style search over full sandbox snapshots.
- Benefit concentrated in long-horizon, multi-service tasks.
- Short (7 pages) preprint; treat as indicative.

## Excerpts
> "higher and more efficient solve rates depend mainly on progress that sits outside the repository, such as databases, services, and other runtime state." (Abstract)

## Relevance to the talk
Snapshots are not only for fast startup or rollback but also a capability for agents themselves (branching exploration). Supports the argument for VM-level sandboxes over git-worktree-only isolation.
