## Summary
Proposes Faaslets: functions isolated by WebAssembly software fault isolation instead of containers, with cgroups for CPU/network, a minimal POSIX host interface, and the ability to share memory regions between co-located functions. Faaslets restore from pre-initialised snapshots for fast start. Compared to a container platform: 2x speed-up and 10x less memory for ML training, double throughput and 90% lower tail latency for inference.

## Key points
- Memory isolation via Wasm SFI; other resources via Linux cgroups.
- Controlled shared memory between functions in one address space avoids serialisation.
- Snapshot restore of initialised Faaslets.
- 2x speed-up with 10x less memory (training); 2x throughput, -90% tail latency (inference).

## Excerpts
> "Faaslets isolate the memory of executed functions using software-fault isolation (SFI), as provided by WebAssembly, while allowing memory regions to be shared between functions in the same address space." (Abstract)

## Relevance to the talk
The "lighter than a container" end of the spectrum: language-level isolation (in the lineage of SFI and NaCl) as a sandbox primitive, with density as the motive.
