## Summary
One agent task can spawn many concurrent sandboxes that all start from the same template and run similar trajectories, so their memory is highly redundant. AgentZip compresses sandbox memory relative to the template and across sibling sandboxes, shifts overhead control to restore-time prefetching, and schedules compression during the idle time while the agent waits for the LLM.

## Key points
- Exploits template-relative and cross-sandbox redundancy.
- Compression scheduled into LLM waiting periods to avoid slowing tool execution.
- Up to 8.7x reduction in sandbox-owned memory vs 2.1x for the Linux configuration.
- Slowdown from aggressive compression cut from up to 3.1x to 1.40x.

## Excerpts
> "these sandboxes are far from independent: they originate from a shared template and execute related trajectories, exposing substantial template-relative and cross-sandbox memory redundancy." (Abstract)

## Relevance to the talk
An example of systems research now treating "agent sandbox" as a workload class with its own shape (idle while the model thinks, bursty during tool calls). Pairs with REAP and microVM snapshot work.
