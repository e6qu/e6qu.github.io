## Summary
Treats an LLM system as an information-processing pipeline and applies classic information flow control. The "f-secure" design splits planning from execution: the planner produces structured executable plans, and a security monitor keeps untrusted inputs out of the planning step, so malicious data cannot steer what the system does. Formal models of both existing and f-secure systems support the security argument.

## Key points
- Disaggregates the LLM system into a context-aware pipeline with dynamically generated structured plans.
- A security monitor filters untrusted input from reaching the planner.
- Provides formal models and security guarantees; evaluated with case studies and benchmarks.
- Code: github.com/fzwark/Secure_LLM_System.

## Excerpts
> "Malicious information from any source may be processed by the LLM and can compromise the query processing, resulting in nearly arbitrary misbehavior." (Abstract)

## Relevance to the talk
One of the first papers to say "don't make the model robust, make the system enforce policy" using decades-old IFC ideas. Sits alongside CaMeL as the information-flow branch of agent isolation.
