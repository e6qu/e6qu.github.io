## Summary
Measures whether unprivileged timing can reveal host page-cache residency across the whole isolation ladder: Docker, gVisor (systrap and KVM platforms), Kata (QEMU, Cloud Hypervisor, Firecracker) and plain QEMU/KVM. Whenever the I/O path exposes shared, host-cacheable file-backed objects (OverlayFS layers, virtio-fs, loop-backed block devices) the signal persists; direct I/O and dedicated block devices largely remove it.

## Key points
- Covers Docker, gVisor, Kata with several VMMs, and QEMU/KVM under multiple cache policies.
- Leakage persists through OverlayFS, virtio-fs exports and loop-backed devices.
- Virtualisation adds latency and noise but does not remove dependence on shared cache state.
- Case study recovers coarse activity from a WordPress+MySQL deployment.

## Excerpts
> "Virtualization therefore reshapes leakage through added latency and algorithmic noise but does not remove the underlying dependence on shared hardware and cache state." (Abstract)

## Relevance to the talk
Shows that the stronger rungs of the container → gVisor → Kata/microVM ladder still share storage paths. Relevant to agent sandboxes that share base images or virtio-fs mounts with the host.
