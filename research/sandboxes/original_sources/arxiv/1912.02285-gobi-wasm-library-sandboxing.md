## Summary
Argues that software fault isolation has never been broadly available because SFI toolchains are hard to build and maintain; Native Client's discontinuation orphaned its users. WebAssembly, backed by all browser vendors, offers a durable path. Gobi compiles C/C++ libraries (libjpeg, libpng, zlib) to Wasm and links them back into native applications as sandboxed modules, and issues a call to make Wasm module sandboxing first-class. Same group behind RLBox library sandboxing in Firefox.

## Key points
- SFI history: NaCl as production SFI, then discontinued.
- Wasm as a sustainable SFI substrate for native code, not only for mobile/web code.
- Prototype tested on libjpeg, libpng and zlib.
- Short paper written January 2019, with a November 2019 update on Wasm tooling.

## Excerpts
> "Without committed support, these tools are not viable, e.g. NaCl has been discontinued, orphaning projects that relied on it." (Abstract)

## Relevance to the talk
Links the history thread (SFI 1993, NaCl 2009) to Wasm as today's in-process sandbox. Good for the "lighter than a process" part of the isolation spectrum.
