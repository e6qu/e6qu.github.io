## Summary
Browser-using agents act through clicks and keystrokes, and writing policies over those UI events is brittle (the "semantic gap"). ceLLMate's insight is to sandbox at the HTTP layer instead: every side-effecting UI action eventually becomes a request to a backend, so policy is enforced there. Implemented as an agent-agnostic browser extension, it blocks prompt-injection attacks in the WASP benchmark with 7.25-15% latency overhead.

## Key points
- Goal: restrict the agent's ambient authority and reduce the blast radius of prompt injection.
- Enforcement point chosen where semantics are clearer (HTTP requests), not where actions originate (UI events).
- Agent-agnostic browser extension; 7.25-15% latency overhead on WASP.
- Homepage: cellmate-sandbox.github.io.

## Excerpts
> "Our core insight is to perform sandboxing at the HTTP layer because all side-effecting UI operations will result in network communication to the website's backend." (Abstract)

## Relevance to the talk
A clean illustration of a classic sandbox design question, *where* to put the reference monitor, answered for a new kind of agent. Parallels the coding-agent practice of enforcing policy at the network proxy rather than per command.
