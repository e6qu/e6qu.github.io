## Summary
Inside a coding agent's sandbox, tools usually carry ambient authority: naming a file is enough to act on it. CapScope derives a task-wide authority ceiling from trusted input *before* any repository content is read, then gives each sub-agent its own typed capabilities stored outside the model's context. An injection can make an agent *ask* for an action, but the harness refuses unless that agent already holds the capability.

## Key points
- Harness-level authorisation; does not require the model to detect malicious text.
- Per-sub-agent capabilities: permissions given to one sub-agent are not available to another.
- Implemented on the Pi coding agent in an orchestrator/sub-agent repair workflow; 300 runs.
- Injected effect executed in 33-47/75 runs under ambient-authority and global-policy baselines vs 3/75 under CapScope.
- Utility: 68/75 repairs completed vs 68-72/75 for baselines.
