## Summary
Introduces vHive, an open-source serverless research framework (containerd + Firecracker), and uses it to show that starting from a snapshot is far from free: functions restored from snapshot run 95% slower on average than memory-resident ones because guest memory is faulted in one page at a time. Since a function touches the same working set each time, REAP records that set and prefetches it, cutting cold-start delay 3.7x on average.

## Key points
- vHive: open-source framework based on containerd and Firecracker.
- Snapshot-started functions: execution time 95% higher on average than memory-resident.
- Cause: lazy page faults bringing state from disk into guest memory.
- Functions access a stable working set across invocations.
- REAP (record-and-prefetch) reduces cold-start delays 3.7x on average.

## Relevance to the talk
The research basis for "fast VM sandboxes via snapshot/restore", which agent-sandbox platforms now rely on for sub-second startup. Shows restore is a memory-paging problem.
