## Summary
The paper that named and systematised *indirect* prompt injection: an attacker never talks to the model, but plants instructions in data the LLM application will later retrieve (web pages, emails, code). The authors show this works against real systems (Bing Chat on GPT-4, code-completion engines) and argue that once an LLM reads attacker data and can call APIs, retrieval becomes something close to remote code execution. It is the root threat model that every later agent-sandboxing paper cites.

## Key points
- Core claim: LLM-integrated applications "blur the line between data and instructions".
- Taxonomy from a computer-security perspective: data theft, worming (self-propagating injections), information-ecosystem contamination, API/tool misuse.
- Demonstrated against Bing's GPT-4-powered chat and code-completion engines, plus synthetic GPT-4 apps.
- Conclusion (2023): effective mitigations were lacking.

## Excerpts
> "We show how processing retrieved prompts can act as arbitrary code execution, manipulate the application's functionality, and control how and if other APIs are called." (Abstract)

> "We argue that LLM-Integrated Applications blur the line between data and instructions." (Abstract)

## Relevance to the talk
The hinge between classic sandboxing and agent sandboxing: the "untrusted code" is now any text the agent reads. Explains why a coding agent must be treated like an untrusted process even when the user and the model are both benign.
