## Summary
RedCode tests whether code agents will *execute* risky code (RedCode-Exec) or *write* harmful software (RedCode-Gen). Each execution test runs inside a Docker environment so its real effects can be checked. Agents more readily refuse obviously dangerous OS operations than subtly buggy code, and risky requests phrased in natural language are refused less than the same thing in code.

## Key points
- RedCode-Exec: 4,050 risky test cases in Python and Bash, 25 vulnerability types across 8 domains (e.g. file systems, websites).
- RedCode-Gen: 160 prompts asking for harmful software.
- Evaluated 3 agent frameworks on 19 LLMs.
- Stronger coding models produce more effective harmful software.
- Docker containers are used as the evaluation sandbox to observe execution results.

## Excerpts
> "agents are more likely to reject executing risky operations on the operating system, but are less likely to reject executing technically buggy code, indicating high risks." (Abstract)

## Relevance to the talk
Evidence that model-level refusal is uneven, so the execution environment has to absorb the mistakes. Also an example of containers used as measurement harness for agent behaviour.
