## Summary
GitHub Copilot agent mode in VS Code runs locally, as the user, in a dedicated "agent host" process. The current default "Copilot harness" is built on the Copilot CLI SDK; the older in-editor "Local harness" is deprecated and due for removal in February 2027. An OS-level sandbox exists but is **off by default** (`chat.agent.sandbox.enabled: "off"`). When it is on, writes are limited to the working directory plus dev-tool caches, outbound network stays **open** unless domain lists are set, and local network is closed. Windows support is experimental. Otherwise the guard is approvals: Manual/Assisted/Allow-all permission levels and `chat.tools.terminal.autoApprove` prefix/regex rules on top of built-in defaults. The early experimental terminal sandbox (`chat.tools.terminal.sandbox.*`, VS Code 1.109, Feb 2026) is now legacy; its engine is `@vscode/sandbox-runtime`, an npm package whose repository field points at Anthropic's sandbox-runtime.

## Key points
- Runs: local agent host process; remote sessions enforce restrictions on the remote host (1.141 release notes, https://code.visualstudio.com/updates/v1_141, 2026-10-07). The same agent UI also hosts Claude and Codex harnesses, each with its own modes (https://code.visualstudio.com/docs/agents/run/approvals).
- Isolation: OFF by default. Supported on macOS 15+ with no extra packages; Linux/WSL2 on glibc, needing bubblewrap >= 0.5.0, `slirp4netns`, util-linux >= 2.35 and iptables (musl/Alpine and WSL1 unsupported); Windows 11 (Experimental), needing BaseContainer and specific cumulative updates. The docs page does not name the macOS primitive. Per the setting description in source, the Copilot harness "uses the SDK runtime's sandbox, including on supported Windows hosts". That is the Copilot CLI runtime, which GitHub documents as Microsoft MXC (Seatbelt/bubblewrap/Windows native, see agent-github-copilot-cli.md), and VS Code source references microsoft/mxc. The Local harness and the agent host's custom terminal tool use `TerminalSandboxEngine`, which shells out to `@vscode/sandbox-runtime`'s `cli.js` with a generated settings file. That package (v0.0.1, published 2026-05-01) lists `github.com/anthropic-experimental/sandbox-runtime` as its repository, i.e. Anthropic's srt (src/vs/platform/sandbox/common/terminalSandboxEngine.ts; package.json). The Local harness has no Windows sandbox (`isTerminalSandboxSupported` returns false on Windows).
- Filesystem: the working directory is writable. `chat.agent.sandbox.fileSystem.allowDevToolAccess` (default `true`) grants read to toolchain dirs and config and read-write to shared build caches. `chat.agent.sandbox.fileSystem.userConfiguredPaths` takes `readwritePaths`, `readonlyPaths` and `deniedPaths` (denied > read-only > read-write). Locally launched MCP and LSP servers are sandboxed by default when the sandbox is on (`chat.agent.sandbox.mcpServers`, `.lspServers`). Even "Allow all" cannot write where the sandbox says read-only.
- Network: with the sandbox on, outbound is allowed by default (`chat.agent.sandbox.network.allowNetwork: true`) and local network is off (`allowLocalNetwork`). A non-empty allowed-domains list restricts destinations, and denied domains win. Windows needs `allowLocalNetwork: true` for the proxy, host rules or credential masking. Credential masking (`chat.agent.sandbox.credentials.*`, `envVars`) mirrors Copilot CLI. Note the default flipped: in the 1.109 experimental terminal sandbox, network was "blocked for all domains by default" (https://code.visualstudio.com/updates/v1_109, 2026-02-04).
- Approvals: Copilot harness levels are Manual (default), Assisted (model-judged) and Allow all; the starting level is set via `chat.defaultConfiguration` → `"approvals"`. The deprecated Local harness has Default / Allow all / Autopilot (Preview) (earlier release notes called the middle level "Bypass Approvals", https://code.visualstudio.com/updates/v1_111), set by `chat.permissions.default`. `chat.tools.terminal.autoApprove` maps prefixes or `/regex/` to `true`/`false`, is evaluated per sub-command (or whole line with `matchCommandLine: true`), and an explicit `false` wins. Other settings: `chat.tools.terminal.enableAutoApprove` (kill switch for rule-based approvals), `chat.tools.terminal.ignoreDefaultAutoApproveRules` (built-in allow/deny rules ship in defaultAutoApproveRules.ts), `chat.tools.global.autoApprove` (YOLO across all workspaces, default false), and `chat.tools.urls.autoApprove`. Approval and sandbox are separate: "Allow Outside Sandbox" is its own prompt, gated by `chat.agent.sandbox.allowUnsandboxedCommands` (default `true`). In the Local harness, commands inside the sandbox are auto-approved unless they need to leave it.
- Enterprise: managed Copilot sandbox settings (Preview) can require sandboxing (`"enabled": true, "allowBypass": false`), lock the session toggle and restrict file and network access. If the sandbox is required but unsupported, commands cannot run. Legacy device policies (`ChatAgentSandboxEnabled`) are deprecated and only supply an overridable default in the Copilot harness. The `ChatToolsAutoApprove` policy can block global auto-approve (https://code.visualstudio.com/docs/enterprise/policies). Claude and Codex harnesses are disabled under managed settings unless allowed.
- History: `chat.tools.terminal.sandbox.enabled` plus `.linuxFileSystem`, `.macFileSystem` and `.network` arrived as Experimental in 1.109 (macOS/Linux only; "On Windows, the sandbox settings have no effect"), with sandboxed commands skipping confirmation. Settings were later renamed to `chat.agent.sandbox.*`. 1.141 (2026-10-07) added Windows, made the Copilot agent host sandbox the main path, and deprecated the legacy settings and policies.

## Relevance to the talk
The most-used IDE agent took a year to converge on an OS sandbox, and it is still opt-in. It went through two engines: Anthropic's srt (repackaged as `@vscode/sandbox-runtime`) for the experimental terminal sandbox, then Microsoft's MXC via the Copilot SDK for the main harness. Along the way the network default flipped from "blocked" to "open". It shows how "approval" and "containment" became separate axes in product UI ("Allow all" no longer means "no sandbox"), and how enterprise policy is becoming the real switch.
