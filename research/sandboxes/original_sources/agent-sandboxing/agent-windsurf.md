## Summary
Windsurf no longer exists under that name. Cognition renamed the Windsurf editor **Devin Desktop** on 2026-06-02. Its agent, Cascade, was replaced as the default by **Devin Local**, which uses the same agent harness as Devin CLI. The legacy Cascade agent stayed available "through July 1st". Cascade had no OS sandbox: it ran terminal commands as the user, gated by four auto-execution levels (Disabled / Allowlist Only / Auto / Turbo) and allow/deny lists. Devin Local adds an **opt-in** OS sandbox (`--sandbox`, or "sandbox mode" that admins can make Required). It uses bubblewrap + socat on Linux, its macOS mechanism is not named in the docs, and Windows is unsupported. Without the sandbox, the agent runs as the user behind a permission-mode and allow/ask/deny rule system.

## Key points
- Product status as of 2026-11-22: "Devin Desktop - the next generation of Windsurf" (Scott Wu and Jeff Wang, 2026-06-02, https://cognition.com/blog/introducing-devin-desktop). The FAQ says "Devin Desktop is the new name for Windsurf" (https://docs.devin.ai/desktop/devin-desktop-faq). Devin Local is "the successor to Cascade as our primary local agent", and legacy Cascade was usable "through July 1st" (https://devin.ai/blog/windsurf-is-now-devin-desktop, 2026-06-02). docs.windsurf.com now 308-redirects to docs.devin.ai. The Windsurf JetBrains plugin (Cascade) is in maintenance mode, and users are pointed to Devin over ACP (FAQ). Third-party ACP agents can also run inside Devin Desktop.
- Runs: a local process on the developer's machine, inside the Devin Desktop IDE (Devin CLI runs the same harness in a terminal). It uses a dedicated agent terminal with `zsh` on macOS and `bash` on Linux (https://docs.devin.ai/desktop/terminal).
- Isolation: **off by default**. Turn it on with `devin --sandbox` (CLI) or sandbox mode in Desktop. Linux: "requires `bubblewrap` (`bwrap`) and `socat`". Windows: "OS-level sandboxing is not currently supported", which hard-fails if requested, including for Devin Desktop over ACP. macOS: the docs claim OS-level isolation but don't name the mechanism (not documented). The sandbox is **fail-closed**: the CLI refuses to start rather than run unsandboxed. Enterprise "Sandbox enforcement mode" is **Optional** (default) or **Required**; a future **Strict** mode may lock the config.
- Legacy Cascade had no OS sandbox. Commands ran in the user's terminal, gated only by the auto-execution level (archived docs.windsurf.com/windsurf/terminal, Wayback snapshot 2026-05-29: https://web.archive.org/web/20260529144606/https://docs.windsurf.com/windsurf/terminal). The JetBrains plugin docs list three levels (Off / Auto / Turbo) (https://docs.devin.ai/windsurf/plugins/cascade/cascade-overview).
- Filesystem: when sandboxed, the OS enforces it. Writable = the workspace plus granted `Write(...)` scopes, and everything else is read-only. Paths in `Read(...)` deny rules are hidden. Mid-session `Write` grants widen the sandbox. The `edit`/`write` tools run in the CLI process, outside the sandbox, so they always prompt. Without the sandbox: "by default, the Devin Local agent can only read/edit files within the workspace" (https://docs.devin.ai/desktop/devin-local/overview). That is a tool-level check, and shell commands are not confined. Cascade's legacy admin control "Restrict Tool Calls to Workspace" was also tool-level.
- Network: open by default, even inside the sandbox ("optionally restricting network traffic"). The `sandbox` config section has `allowed_domains`, `denied_domains` and `network_mode` (`"full"` default, or `"limited"` = GET/HEAD/OPTIONS only). When configured, "a managed network proxy starts on loopback" and child traffic is forced through it. The enterprise allowlist replaces the user's; enterprise denylists add to the user's. The docs flag this: "Sandbox network filtering is currently unstable."
- Escape hatch: `sandbox.excluded.allow` / `.ask` / `.deny` with `Exec(...)` rules let named commands run outside the sandbox, for example `git` that needs credentials. A team-level `deny` beats a user `allow`. Commands that can't be parsed stay inside.
- Approvals (Devin CLI / Devin Local, https://docs.devin.ai/cli/reference/permissions): the modes are **Normal** (default; reads auto-run, writes and shell prompt), **Accept Edits**, **Smart** (a fast model auto-approves actions it judges safe), **Bypass** (everything auto-approved, no OS isolation; config value `"dangerous"`), **Autonomous** (shell and fetch auto-approve because the sandbox contains them; the only mode available with `--sandbox`) and **Plan**. Set via `--permission-mode <mode>`, `DEVIN_PERMISSION_MODE`, or the config key `permission_mode`. Rules use `allow`/`ask`/`deny` with `Exec(git status)`-style syntax. Deny has the highest priority. Desktop calls the modes "Code, Smart, Ask, Plan, and Bypass Permissions".
- Approvals (legacy Cascade): **Disabled**; **Allowlist Only**; **Auto** (the model judges safety; premium models only); **Turbo** ("All commands are auto-executed immediately, except those in your deny list"). Allow and deny lists existed per user and team-wide. Admins could cap the maximum level (archived terminal doc). After the switch, these settings act only as a fallback for Devin Local, until admins write a CLI permission policy (https://docs.devin.ai/cli/enterprise/controls).
- Enterprise: org deny/ask rules override user rules and Bypass. Admins can enforce sandbox mode, restrict selectable modes and set org domain lists. An "Enable Cascade" control can turn off the legacy agent (https://docs.devin.ai/desktop/terminal, /cli/enterprise/controls). Restricted Mode (untrusted workspace) disables all agents and hooks (Devin Local overview).

## Excerpts
> "The `--sandbox` flag runs the CLI with OS-level isolation, enforcing writable paths and `deny` rules at the operating-system level and optionally restricting network traffic." (Sandbox, intro)

> "If sandbox resolution fails ... the CLI will **refuse to start** rather than running unsandboxed." (Sandbox, How the sandbox works)

> "Use Bypass when you want unrestricted execution without OS-level isolation; use `--sandbox` (which selects Autonomous) when you want unattended execution with OS-enforced limits" (Devin CLI permissions, Autonomous Mode)

> "Turbo: All commands are auto-executed immediately, except those in your deny list." (archived Windsurf Terminal docs, Auto-Execution Levels)

## Relevance to the talk
This is the clearest 2026 case of an IDE agent moving from "approval levels plus a deny list" (Cascade's Turbo mode was effectively YOLO with a blacklist) to a Claude-Code-style opt-in bubblewrap sandbox with a loopback proxy. It makes the same design choices: fail-closed, an "autonomous only when sandboxed" mode, and file-edit tools outside the sandbox. The gaps are honest ones: off by default, Windows unsupported, network filtering marked "unstable". The rename itself is also slide material. Talks citing "Windsurf/Cascade" in 2026 are describing a retired agent.
