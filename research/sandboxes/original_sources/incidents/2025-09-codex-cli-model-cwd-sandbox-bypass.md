## Summary
Codex CLI's sandbox gives write access to a "writable root", meant to be the folder where the user started the session. Due to a bug, Codex could take the **model-generated `cwd`** of a tool call as that writable root. A model (or a prompt injection steering it) could therefore pick any directory, such as `~` or a dotfile directory, as `cwd` and get write access and command execution there inside a sandbox that looked enforced. The network-off restriction still held. OpenAI fixed it in 0.39.0 by canonicalising the boundary and deriving it from the user's session start directory, not from model output.

## Key points
- Affected: `@openai/codex` 0.2.0 through 0.38.0; Codex IDE extension through 0.4.11. Severity high.
- Mechanism (advisory): the sandbox policy boundary was built from a value the model controls. The fix "canonicalizes and validates that the boundary used for sandbox policy is based on where the user started the session, and not the one generated by the model."
- Not affected: the network-disabled sandbox restriction.
- The same bug class reappeared in Cursor: CVE-2026-50548, "Cursor Desktop sandbox escape via agent-controlled working directory" (see [2026-06-agent-sandbox-escape-advisories.md](2026-06-agent-sandbox-escape-advisories.md)).
- Another policy-construction bug of the same family: Anthropic's `sandbox-runtime` < 0.0.16 (CVE-2025-66479, GHSA-9gqj-5w7c-vx47, 2025-12-04, reported by Ben Drucker) "did not properly enforce a network sandbox if the sandbox policy did not configure any allowed domains". An empty allowlist failed open instead of meaning "no network".
- No in-the-wild exploitation is claimed. This is a researcher-reported vulnerability.

## Excerpts
> "Codex CLI could treat a model-generated `cwd` as the sandbox's writable root, including paths outside of the folder where the user started their session." — advisory

> "This logic bypassed the intended workspace boundary and enables arbitrary file writes and command execution where the Codex process has permissions" — advisory

## Would a mature sandbox have stopped it?
This *was* a mature-looking sandbox: OS-enforced, on by default, with network off. It failed at the **policy-construction** step. The fs write scope came from an input the confined party controlled. The control that was missing is a basic rule of sandbox design: **the boundary must be computed only from trusted inputs (user/session config), never from the requests of the code being confined**, and an empty or unresolvable policy must fail closed (cf. CVE-2025-66479 above). Defence in depth would have reduced the impact: a VM or container whose only mount is the workspace, so that no host path exists to name, plus **snapshots** of the home directory. Neither was in Codex's default local setup.

## Relevance to the talk
A clean illustration that "we use Seatbelt/Landlock" is not the end of the story. The kernel mechanism was fine; the agent harness handed the prisoner the key. It also shows a bug class that recurs across vendors (Codex 2025, Cursor 2026).
