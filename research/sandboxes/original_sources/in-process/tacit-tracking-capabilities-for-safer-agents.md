## Summary
TACIT is a "safety harness" for coding agents built by EPFL's LAMP group. The agent is meant to have no shell or file tools of its own: it writes Scala 3 snippets, and an MCP server type-checks them with capture checking in safe mode and runs them in a JVM REPL. The only way to the outside world is a typed capability library (file system, process exec, network, sub-LLM). Capabilities are scoped to `request*` blocks and cannot escape them. A `Classified[T]` wrapper accepts only pure functions in `map`, which enforces at compile time that secrets can be computed on but not printed or sent anywhere. The paper reports 100% security in its leak benchmark with classified mode on, and utility on τ²-bench and SWE-bench Lite comparable to ordinary tool calling.

## Key points
- **Architecture** (README): (1) the Scala 3 compiler with capture checking in *safe mode*; (2) a Scala REPL that runs compiled code, either stateless or as a session; (3) a "capability safety library", described as "the sole gateway" to the file system, process execution, network and sub-agents. It is delivered as an MCP server (`execute_scala`, `create_repl_session`, `execute_in_session`, `show_interface`, …) and needs JDK 17+.
- **The host must disable the agent's own tools.** The README recommends launching Claude Code with `--disallowedTools "Bash,Read,Write,Edit,WebFetch"`. Without that, the agent can bypass the REPL entirely. The follow-on ATC agent (lampepfl/atc) removes this setup step.
- **Two layers of enforcement.** By default a *static regex validator* (`CodeValidator.scala`) rejects source containing forbidden patterns: `java.io`, `java.nio`, `ProcessBuilder`, `java.net`, `HttpClient`, `.asInstanceOf[`, `caps.unsafe`, `getDeclaredMethod`, `setAccessible`, `Class.forName`, `sun.*`, `System.getenv`, `new Thread`, `ClassLoader`, `dotty.tools`, `//> using` directives, and others. `--safe-mode` (on by default in the current CLI) also imports `language.experimental.safe` so that the compiler enforces the subset itself.
- **Capability API.** `requestFileSystem(root){…}`, `requestExecPermission(Set("ls","cat")){…}` and `requestNetwork(Set(host)){…}`. Capability classes extend `caps.SharedCapability` and have `private[library]` constructors, so agent code cannot forge them. Each `request*` scope is also bounded at runtime by operator configuration: `allowedRoots` (defaults to the working directory, with symlinks resolved), `commandPermissions` and `networkPermissions` globs, and `strictMode` (a built-in denylist of shells, interpreters, curl and similar). A command has to pass both the in-code scope and the operator allowlist.
- **Classified data.** Paths matching gitignore-style patterns (default `.ssh`, `.gnupg`, `.env*`, `.netrc`, `.npmrc`, `.aws`, `.kube`, …) come back as `Classified[String]`. `Classified.map` accepts only pure `T -> U` functions. A dual-LLM `chat(Classified[String]): Classified[String]` sends the content to a trusted local model. `secretHeaders` and `httpPostClassified` let a secret reach an allowlisted host without the agent's code ever observing it.
- **Three claimed guarantees:** capability safety (capabilities cannot be forged or forgotten), capability completeness (all safety-relevant effects go through capabilities), and local purity.
- **Threat model** (§3.1). Trusted: the Scala compiler with capture checking and safe mode, the TACIT library, the runtime (JVM), and the optional local LLM. Untrusted: the cloud LLM ("potentially byzantine"), all agent-submitted code, and all external content.
- **Results.** Leak benchmark: 131 trials per model and mode, built from AgentDojo-style injections on a Scala project with a `secrets/` tree. In classified mode both Claude Sonnet 4.6 and MiniMax M2.5 scored 100% security, with utility of 99.2% and 90.0%. Unclassified, Sonnet scored 98.5% and MiniMax 91.6% (8 of 11 malicious tasks extracted secrets). On τ²-bench, Scala beat tool calling by +0.8 to +3.7 points. On SWE-bench Lite, MiniMax dropped slightly (41.67% vs 43.33%), which the authors attribute to coding tasks relying on "shell interaction patterns". Compile-and-retry overhead was small, and compilation is sub-second once the JVM is warm.
- **Stated non-goals and limits** (§5): output correctness; **side channels** ("We do not cover covert channels such as timing or termination"); **external commands** ("External processes spawned by the agent escape the Scala safe-mode boundary, so the static guarantee degrades to that of the underlying allowlist"). The paper recommends combining TACIT with OS sandboxing "for defense in depth" against escapes of the runtime itself (JVM bugs, native interop).
- **Execution timeout is best-effort** (README). A pure CPU loop that ignores interrupts keeps running: "Hard preemption would require process-level isolation; this knob is a robustness guard, not a sandbox boundary."
- **`Classified` protects confidentiality, not integrity** (README). With `classifiedWrite` left at its default `true`, an agent can overwrite e.g. `.ssh/authorized_keys`.
- **Known leak, open issue #15** ("Vulnerablity: 1-bit leak in writeClassified", 2026-11-17). A `map` that throws on a secret-dependent condition makes `writeClassified` skip creating the file. `access(path).exists` then reveals one bit, and binary search recovers the whole secret. This is the termination/exception channel the paper lists as a non-goal, and it is reachable through the library's own API. (ATC's README says it closes this: "a computation that fails on a secret is not turned into a one-bit oracle".)
- **Positioning vs CaMeL** (§related work): CaMeL tracks taint on data with a runtime monitor in a custom Python-like interpreter. TACIT tracks capabilities on code statically, using the stock Scala 3 compiler. The paper calls Cedar-based AgentCore Policy "little more than access lists" and argues that sandboxes "cannot enforce information-flow properties within the permitted operations".
- **Follow-on:** LACUNA (arXiv 2605.28617, Zhao, Xu, Bračevac, Pham, Wu, Odersky, 2026-05-27) makes each agent action a typed hole `agent[T](task)` that is type-checked against the surrounding program before it runs. On BrowseComp-Plus, 8.6% of generations are rejected before execution. On τ²-bench it solves 76.0% of 392 tasks.

## Relevance to the talk
This is the flagship of the in-process / language-capability sub-type and the main primary source behind Biały's talk. It makes the strongest claim of the class (compile-time information-flow guarantees, model-independent) and is unusually candid about where the claim stops: anything you `exec` is ordinary OS code, side channels are out of scope, and the TCB includes the JVM and an experimental compiler feature. The 1-bit `writeClassified` leak shows the familiar failure pattern of language sandboxes: the type system is sound, but the trusted library leaks. Pair this note with `scala-safe-mode.md`, `scala-capture-checking.md` and `lampepfl-atc.md`. For the dual-LLM comparison, cite `../arxiv/2503.18813-camel.md`.
